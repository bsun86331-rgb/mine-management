# 共享生产任务看板 V2

## 当前范围

采用同一浏览器、同一站点来源的本机数据联动，不宣称跨电脑、跨手机同步。调度权限沿用已审核 personnelRecords 身份；这是本机界面权限，接入服务端时须用 Supabase Auth 和 RLS 再强制执行。

## 操作流程

1. 管理员先维护并审核人员、设备档案；调度通过运输区域管理建立装载区、卸载区。
2. 已审核的车队长 / 调度进入 dispatch.html，设置白班与夜班起止时间。两班必须连续覆盖24小时。
3. 点击下发任务进入看板编辑；添加生产组，选择A/B人员班组、煤/岩石、装载区及多个卸载区。
4. 点击设备和人员卡片配置挖机、汽车及司机；添加辅助车辆、司机和作业内容。
5. 点击绑定并发布。其他岗位读取共享看板，点击卡片查看档案；它们没有修改入口。
6. 调度点击调整绑定进入同一编辑界面。取消不保存；发布前重新验证可调配资源、请假、维修、重复绑定及数据版本。

## 日期与统计口径

- A/B是人员班组，与白班/夜班完全独立。
- 生产日从白班开始时刻算起，到次日白班开始为止。午夜后的夜班仍属于前一生产日。
- 默认自动显示当前班。手动选择日期或另一班后维持该选择，点击回到当前班恢复自动切换。
- 总车数、A/B车数和煤车数按完成运输趟次计数，跨 tripRecords / driverTripRecords 去重，待审核及作废记录不计数。
- 汽车和全部设备台数分开显示；设备出勤按所选班次的有效绑定计数。
- 人员出勤按考勤打卡或调度确认记录计算，人员绑定数另列。绑定不伪造考勤。

## 数据与兼容

- 唯一看板数据源：localStorage.mineProductionBoardV2，包含时间设置、日期/班次看板、版本、修改审计和每次绑定快照。
- 新模块：js/production-board-core.js（领域逻辑）、js/production-board.js（界面与本机持久化）、css/production-board.css。
- 新看板派生 dispatchPublishedTasks / dispatchShiftExecutions 作为司机、挖机、辅助车辆现有作业流程的兼容缓存，不保留旧任务创建器。
- 当前班投影为 active，未来班为 scheduled，已结束班为 handed_over。资源可在不重叠的班次重复使用。
- 同一生产日期和班次的旧任务可以读入新看板；发布后旧任务归档，不删除历史运输趟次。
- 调度的维修、考勤、奖罚、GPS、请假、临时卸料和运输区域模块保留。原有多套任务表单、班次发布器与绑定编辑器已删除。
- 17个首页及岗位页面加载同一个看板组件。修改资源或时间会通过浏览器 storage 事件和5秒轮询同步。

## 验证

运行 node --test tests/production-board-core.test.js，覆盖跨午夜班次、时间覆盖规则、岗位权限、资源筛选、重复绑定、运输统计、考勤与旧作业端兼容数据。

后续联网版本需要服务端统一数据源、事务绑定、资源占用约束、服务器时间及调度写入策略；不能把本机岗位字段当作联网授权依据。
